# Dotbox

Dots & Boxes(점 잇기)를 **알파제로 방식 강화학습**으로 처음부터 학습시키는 저장소.
사람이 만든 전략은 하나도 안 넣었고, 신경망이 자기 자신과 두면서 배운다.
깃허브 액션이 알아서 돌리므로 내 기기는 꺼놔도 된다.

## 게임 규칙

점 격자에서 번갈아 변을 하나씩 긋는다. 네 변이 다 채워진 칸은 마지막 변을 그은 사람이
가져가고, 칸을 따면 **한 번 더** 둔다. 모든 변이 그어지면 끝이고 칸을 많이 딴 쪽이 이긴다.

겉보기와 달리 전략이 깊다. 잘 두면 일부러 몇 칸을 내주고 나중에 긴 줄을 통째로 먹는다.
그게 나오는지가 이 학습의 관전 포인트다.

## 시작하기

1. 저장소를 **Public** 으로 만든다 (공개면 액션 실행 시간 제한이 없다)
2. 이 파일들을 그대로 올린다. `train.yml` 은 반드시 `.github/workflows/` 안에 둔다
3. Settings → Actions → General → Workflow permissions 를 **Read and write permissions** 로 바꾼다
4. Actions 탭 → train → **Run workflow**

이후로는 한 번 실행이 끝날 때마다 스스로 다음 실행을 걸어서 계속 돈다.

## 결과 보기

**`state/REPORT.md`** 하나만 보면 된다. 회차별 성적표와 그래프가 들어 있다.

숫자 네 가지가 찍힌다.

| 숫자 | 뜻 | 어떻게 읽나 |
|---|---|---|
| 정답 일치율 | 완전 탐색으로 구한 '진짜 정답'과 신경망의 선택이 맞는 비율 | 작은 판(3x3)에서만 잴 수 있다. 이게 오르면 제대로 배우는 중 |
| 무작위 상대 승률 | 아무 데나 긋는 상대 | 금방 100%가 된다. 여기서 안 오르면 학습이 아예 안 도는 것 |
| 욕심쟁이 상대 승률 | 딸 수 있으면 무조건 따고, 아니면 안 내주는 수를 두는 상대 | 이걸 넘기려면 '일부러 내주고 나중에 크게 먹기'를 배워야 한다 |
| 이전 버전 상대 승률 | 새로 학습한 신경망 vs 지금 쓰는 신경망 | 55%를 넘으면 교체된다. 계속 50% 근처면 더 이상 안 느는 중 |

정답 일치율에는 두 가지가 찍힌다. **탐색**은 MCTS까지 돌린 최종 선택, **직감**은 신경망이
생각 없이 바로 고른 수. 직감이 탐색을 따라 올라오면 신경망 자체가 세지고 있다는 뜻이다.

## 학습이 잘 안 될 때 보는 곳

- 무작위 상대 승률이 100%에 안 붙는다 → 파이프라인이 고장난 것. 규칙 구현이나 손실 계산 의심
- 정답 일치율이 안 오른다 → `sims`(생각 횟수)나 `games_per_iter`(판수)가 너무 적음
- 이전 버전 상대가 계속 40%대 → 학습률(`lr`)이 너무 크거나 `train_steps`가 과함
- 욕심쟁이만 못 이긴다 → 판이 작아서 긴 줄 전략이 나올 자리가 없을 수 있음. 판을 키워야 함

## 단계

`config.json` 의 `stages` 순서대로 돈다. 한 단계가 끝나면 자동으로 다음 단계로 넘어간다.

1. **3x3** (변 24개) — 완전 탐색으로 정답을 다 알 수 있는 크기.
   여기서 정답 일치율이 안 오르면 그 아래는 볼 것도 없다. 회차당 30초~1분
2. **5x5** (변 60개) — 본 실행. 사슬 전략이 나타나는 최소 크기. 회차당 5분 안팎

9x9로 키우고 싶으면 `stages` 에 `{"name":"9x9","rows":9,"cols":9,...}` 를 덧붙이면 된다.

## 멈추기

`state/STOP` 이라는 빈 파일을 만들어 커밋하면 다음 실행을 걸지 않는다.
(깃허브 웹에서 Add file → Create new file → 이름에 `state/STOP` → Commit)

다시 돌리려면 그 파일을 지우고 Run workflow. 모든 단계가 끝나면 `state/DONE` 이 생기고
스스로 멈춘다.

## 설정 (`config.json`)

| 항목 | 뜻 |
|---|---|
| `sims` | 한 수를 정할 때 MCTS가 돌려 보는 횟수. 크면 세지고 느려짐 |
| `games_per_iter` | 한 회차에 둘 자기대국 판수 |
| `buffer_size` | 학습에 쓰려고 쌓아 두는 수의 최대 개수 |
| `train_steps` | 한 회차에 신경망을 몇 번 갱신할지 |
| `arena_games` | 새 신경망과 지금 신경망을 몇 판 붙여 볼지 |
| `promote_winrate` | 이 승률을 넘으면 새 신경망으로 교체 |
| `exact_check` | 정답 일치율을 잴지 (변 26개 이하에서만 가능) |
| `max_minutes` | 한 실행에서 돌릴 시간. 액션 제한(6시간)보다 짧게 |

## 코드 구조

| 파일 | 하는 일 |
|---|---|
| `dab/game.py` | 규칙. 판을 비트마스크 하나로 표현 |
| `dab/solver.py` | 완전 탐색으로 작은 판의 정답표를 만듦 |
| `dab/net.py` | 정책망 + 가치망 (PyTorch MLP) |
| `dab/mcts.py` | 몬테카를로 트리 탐색. 칸을 따면 한 번 더 두는 규칙 처리가 핵심 |
| `dab/arena.py` | 실력 재기용 상대들 (무작위, 욕심쟁이) |
| `dab/parallel.py` | 자기대국·대결을 코어 수만큼 나눠 돌림 |
| `dab/train.py` | 자기대국 → 학습 → 교체 판정 → 기록 |
| `dab/report.py` | 성적표와 그래프 생성 |

## 직접 돌려보기

```bash
pip install -r requirements.txt
python -m dab.train --config config-smoke.json   # 2x2 판으로 몇 분이면 한 바퀴
python -m dab.train --config config.json         # 본 실행
```

## 알아둘 것

- 강화학습은 죽지 않고 **조용히 이상한 걸 배우는** 경우가 많다. 그래서 정답 일치율 같은
  객관적인 잣대를 같이 찍는다. 숫자가 이상하면 며칠 태우기 전에 멈추는 게 낫다
- 3x3 정답: 빈 판의 값이 **-3**. 양쪽이 최선을 다하면 후공이 6대 3으로 이긴다
- 액션 무료 한도는 공개 저장소면 사실상 무제한이지만, 며칠 돌려서 결과가 나오면 끄는 게 낫다
